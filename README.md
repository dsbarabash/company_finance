# Система учета и анализа финансов

## Описание проекта

Данная база данных разработана для автоматизации учета доходов и расходов компании, а также для проведения финансового анализа. Система позволяет вести детальный учет финансовых операций, формировать отчеты, контролировать бюджеты и анализировать прибыльность бизнеса в различных разрезах.

## Структура базы данных

### Основные сущности

База данных состоит из 12 таблиц:

**Справочники:**
- `companies` - компании, для которых ведется учет
- `departments` - структурные подразделения компаний
- `employees` - сотрудники, ответственные за операции
- `counterparties` - контрагенты (клиенты, поставщики, партнеры)
- `currencies` - валюты для мультивалютного учета
- `transaction_types` - классификатор типов операций (доходные/расходные)
- `income_categories` - категории доходов для детальной аналитики
- `expense_categories` - категории расходов для контроля затрат
- `invoice_statuses` - статусы счетов (оплачен, не оплачен, просрочен)

**Основные таблицы:**
- `transactions` - главная таблица учета всех финансовых операций
- `budget_plans` - бюджетные планы для план-факт анализа
- `monthly_reports` - агрегированные финансовые отчеты по месяцам

### Связи между таблицами

Все таблицы связаны через внешние ключи, что обеспечивает целостность данных. Транзакции привязаны к компаниям, отделам, сотрудникам, контрагентам, типам операций и категориям. Это позволяет анализировать финансы в любом разрезе: по компании, по отделам, по контрагентам, по типам операций.

## Хранимые процедуры и функции

### Пользовательские функции

**fn_get_company_balance**
Возвращает баланс компании (разницу между доходами и расходами) на указанную дату. Позволяет быстро получить текущее финансовое состояние без сложных запросов.

**fn_calculate_profit_margin**
Рассчитывает рентабельность (маржинальность) за указанный период в процентах. Используется для оценки эффективности бизнеса.

**fn_format_currency**
Форматирует числовые суммы с добавлением символа валюты. Упрощает формирование отчетов для пользователей.

### Хранимые процедуры

**sp_create_income_transaction**
Создает доходную транзакцию с автоматической проверкой корректности данных. Упрощает ввод доходных операций и гарантирует заполнение всех обязательных полей.

**sp_create_expense_transaction**
Создает расходную транзакцию. Аналогично предыдущей, но для расходных операций.

**sp_reconcile_transactions**
Массово подтверждает транзакции за указанный период. Используется для сверки данных и закрытия отчетных периодов.

**sp_update_budget_plan**
Создает или обновляет бюджетный план для отдела на месяц. Позволяет вести актуальные плановые показатели.

**sp_generate_monthly_financial_report**
Генерирует сводный финансовый отчет за указанный месяц. Агрегирует все доходы и расходы, вычисляет прибыль и рентабельность, сохраняет результат в отдельную таблицу для быстрого доступа.

## Техники оптимизации производительности

### Индексы

Для ускорения работы с данными созданы следующие индексы:

1. **idx_transactions_date** - индекс по дате транзакции. Ускоряет отчеты за период и фильтрацию по датам.

2. **idx_transactions_company_date** - составной индекс по компании и дате. Критически важен для формирования отчетов по конкретной компании за период.

3. **idx_transactions_department** - индекс по отделу. Ускоряет аналитику в разрезе подразделений.

4. **idx_transactions_type** - индекс по типу операции. Ускоряет фильтрацию доходов/расходов.

5. **idx_transactions_counterparty** - индекс по контрагенту. Ускоряет анализ по клиентам и поставщикам.

**Влияние на производительность:**
Индексы сокращают время выполнения запросов с секунд до миллисекунд при выборке по датам, компаниям и контрагентам. Без индексов запросы к таблице транзакций при большом количестве записей (более 100 тысяч) могут выполняться минутами. С индексами - менее секунды.

### Представления (Views)

Созданы три представления для упрощения сложных запросов:

**v_department_balance**
Показывает баланс по каждому отделу с использованием CTE. Позволяет быстро получить информацию о доходах, расходах и рентабельности каждого подразделения.

**v_counterparty_summary**
Сводная информация по контрагентам: количество транзакций, общая выручка и затраты. Используется для анализа ключевых клиентов и поставщиков.

**v_budget_vs_actual**
Сравнивает плановые и фактические показатели по месяцам и отделам. Использует подзапросы для расчета фактических данных.

**Влияние на производительность:**
Представления инкапсулируют сложную логику и позволяют использовать их как простые таблицы. Это упрощает разработку отчетов и обеспечивает единообразие расчетов во всей системе.

### CTE (Общее табличное выражение)

В представлении v_department_balance используется CTE для предварительной агрегации данных по отделам. Это позволяет:
- Избежать многократного обращения к таблицам
- Упростить читаемость сложного запроса
- Повысить производительность при большом количестве данных

### Подзапросы

В представлении v_budget_vs_actual используются подзапросы для расчета фактических доходов и расходов по месяцам. Подзапросы позволяют получать данные из разных таблиц в одном запросе без дополнительных JOIN.

## Триггеры для автоматизации

### trigger_transactions_update
Автоматически обновляет поле `updated_at` при любом изменении записи в таблице транзакций. Обеспечивает аудит изменений без участия разработчика.

**Назначение:** Позволяет отслеживать, когда и кем были изменены финансовые записи.

### trigger_validate_transaction_categories
Проверяет соответствие категорий типу транзакции. Для доходных операций обязательно заполнение категории дохода, для расходных - категории расхода.

**Назначение:** Обеспечивает целостность данных на уровне бизнес-логики.

## Мониторинг производительности

Для контроля работы базы данных и своевременного выявления проблем производительности используется набор мониторинговых запросов. Они позволяют отслеживать текущее состояние системы и оперативно реагировать на возникающие проблемы.

1. **Мониторинг блокировок** - Запрос позволяет выявить заблокированные запросы, которые могут замедлять работу всей системы.
   Что показывает:
    Какие запросы выполняются в данный момент
    Сколько времени они уже выполняются
    Есть ли ожидания (wait_event) - признаки блокировок

3. **Мониторинг активных сессий** - Позволяет оценить нагрузку на базу данных и количество подключений.
   Что показывает:
    Количество активных сессий по пользователям
    Состояние подключений (active, idle, idle in transaction)

4. **Мониторинг долгих запросов** - Выявление запросов, которые выполняются дольше 5 секунд.
   Что показывает:
    Запросы, превышающие порог времени выполнения
    Полный текст запроса для анализа

5. **Мониторинг размера таблиц** - Отслеживание роста базы данных для планирования ресурсов.
  Что показывает:
   Общий размер каждой таблицы
   Размер данных и индексов отдельно

## Безопасность данных

Настроены три роли с разным уровнем доступа:

**finance_admin**
Полный доступ к данным и структуре базы. Может создавать, изменять и удалять любые объекты.

**finance_accountant**
Может читать, создавать и изменять финансовые данные, но не может изменять структуру базы или удалять таблицы.

**finance_viewer**
Только чтение данных. Не может вносить изменения.

**Механизмы защиты:**
- Разделение доступа по принципу минимальных привилегий
- Запрет опасных операций (DROP, TRUNCATE) для рядовых пользователей

## Преимущества решения

1. **Полнота учета** - система покрывает все основные потребности финансового учета.

2. **Гибкость аналитики** - возможность строить отчеты в различных разрезах (по компаниям, отделам, контрагентам).

3. **Автоматизация** - триггеры и хранимые процедуры автоматизируют рутинные операции.

4. **Производительность** - оптимизированная структура с индексами обеспечивает быструю работу с большими объемами данных.

5. **Безопасность** - ролевая модель доступа защищает данные от несанкционированного доступа.

6. **Масштабируемость** - структура позволяет легко добавлять новые компании, отделы и типы операций без изменения архитектуры.

7. **Аудит** - отслеживание изменений и контроль версий данных.

## Заключение

Разработанная система учета и анализа финансов предоставляет полный набор инструментов для ведения финансового учета компании. Благодаря продуманной структуре, оптимизации запросов и автоматизации процессов, система обеспечивает высокую производительность и надежность даже при работе с большими объемами данных.
